# 三通道融合权重实验设计

## 1. 目标与边界

本实验只验证 CH3、CH4、CH5 三个既有 43 维 CatBoost 单通道模型的概率融合策略。比较等权概率融合、全局通道权重融合和类别级通道权重融合，并判断是否值得替换正式软件当前的等权融合。

本阶段不修改正式软件逻辑，不修改 43 维特征、预处理参数、类别顺序或 P1@500 CatBoost 参数；不做 OOD、SHAP、硬标签投票、权重网格搜索、自动权重学习或其他扩展。实验代码和实验结果独立提交，不能覆盖既有 parent_group 评估资产或部署模型。

## 2. 数据隔离

沿用既有 parent_group 划分和三通道同组边界。strict parent_group 测试集在策略选择期间完全隔离，仅允许 train_dev parent groups 参与权重计算和方法选择。

现有结果目录没有保存足以直接复算三种融合策略的完整训练侧 OOF 六类概率，因此需要按原 grouped CV 规则和固定 P1@500 参数重新生成 CH3、CH4、CH5 的 OOF 概率。这里训练的折内模型只是实验评估模型，不替换或修改正式部署模型。

## 3. 训练侧交叉拟合

采用外层 grouped CV 评估融合方法。每个外层验证折的权重只能由其他折的 OOF 预测指标计算，不能使用当前验证折标签计算该折权重。这样避免在同一批样本上既估计权重又评价权重。

每个折必须保证：

- parent_group 不跨训练与验证边界；
- 同一 record_id 的 CH3、CH4、CH5 处于同一折；
- 三通道窗口键、record_id 和真实标签严格对齐；
- 特征顺序固定为既有 43 维，不做缩放；
- CatBoost 参数保持 P1@500，不重新调参。

完成外层交叉拟合后，使用全部 train_dev OOF 结果计算唯一的最终全局权重和类别级权重。最终策略及权重冻结后，才可运行一次 strict parent_group 独立验证。

## 4. 融合方法

### 4.1 等权概率融合

对当前有效通道的六类概率逐类取算术平均。只有一个有效通道时直接使用该通道概率。

### 4.2 全局通道权重融合

以训练侧 grouped CV 的通道 Macro-F1 构造权重：

`w_c = MacroF1_c / sum(MacroF1_c)`

对每个类别使用同一组通道权重。缺失通道时，仅在当前有效通道内重新归一化，不能将缺失通道权重保留在分母中。

### 4.3 类别级通道权重融合

以训练侧 grouped CV 的 class-wise F1 构造 `w_{c,k}`：

`S_k = sum(w_{c,k} * P_{c,k}) / sum(w_{c,k})`

缺失通道时按类别在剩余有效通道中重新归一化。如果某类别的可用权重和为零，则该类别回退为有效通道等权得分。得到六个 `S_k` 后再归一化为总和为 1 的六类概率。

权重 JSON 必须保存来源、CV 范围、公式、原始指标、归一化结果、类别顺序、通道顺序和生成时间，禁止写死经验权重。

## 5. 有效通道组合

三种方法都必须支持所有非空组合：CH3、CH4、CH5、CH3+CH4、CH3+CH5、CH4+CH5、CH3+CH4+CH5。融合始终使用六类概率，不允许硬标签投票。

主结论以三通道完整输入为主，同时报告 1、2 个通道组合的稳定性和缺失通道敏感性。

## 6. 评价层级与指标

### 6.1 Window level

在三通道严格对齐的窗口键上融合，输出 Macro-F1、各类别 recall/F1、混淆矩阵和分歧统计。

### 6.2 Record level

先对每个通道同一 record_id 的全部窗口概率取平均，再执行通道融合。输出 Macro-F1、各类别 recall/F1、混淆矩阵和分歧统计。

不得把 parent_group 聚合指标替代用户要求的 record-level 指标；可以另附 parent_group 层级作为审计信息，但不作为必需输出的替代品。

## 7. 分歧与过度依赖分析

至少统计：

- 三通道预测完全一致、两对一和三者均不同的样本数；
- 单通道高概率反对其余通道的样本；
- 不同融合策略改变等权结论的样本；
- 每个通道的全局权重、类别级最大权重、最大/最小权重比；
- 各有效通道组合相对完整三通道的指标变化。

过拟合判断至少依据：外层折增益方向是否一致、折间标准差、训练侧交叉拟合提升与 strict parent_group 提升是否同向，以及类别级改善是否以其他类别明显退化为代价。

## 8. 策略选择规则

最终策略只根据训练侧嵌套式 grouped CV 决定，strict parent_group 结果不得用于反向选策略或改权重。

- 若加权方法提升很小、折间不稳定或仅改善少数类别并损害整体，保留等权。
- 若全局加权在多数外层折稳定提高 window-level 和 record-level Macro-F1，且无明显通道集中，可推荐全局加权。
- 类别级加权只有在整体指标稳定提升、主要类别无明显退化且权重不过度集中时才可推荐。
- strict parent_group 只用于报告冻结策略的独立验证。如果其结果退化，应如实报告，不得回头更换策略。

## 9. 输出目录与文件

输出到新的不可覆盖目录：

`实验结果/三通道融合权重实验_YYYYMMDD/`

至少包含：

- `fusion_summary.csv`
- `channel_weights.json`
- `classwise_weights.json`
- `train_side_cv/` 下的折定义、OOF 概率、逐折指标和汇总
- `strict_parent_group/` 下冻结策略的一次独立验证结果
- 各方法 window/record confusion matrix
- 各方法、各层级、各类别 recall/F1
- 三通道分歧样本统计及明细
- 输入文件哈希、参数、随机种子、环境和运行 manifest
- `README.md`，明确策略选择依据、最终权重、过拟合判断、strict 结果和部署建议

输出采用临时目录完整生成、验收后原子发布；目标目录已存在时拒绝覆盖。

## 10. 验收

验收必须证明：strict parent_group 标签未参与权重计算；各折 parent_group 与 record_id 无泄漏；三通道 OOF 键完全对齐；所有融合概率有限、位于 0 到 1 且和为 1；1/2/3 通道组合正确重新归一化；输入评估模型和既有实验结果哈希保持不变；实验可由 manifest 和固定命令复现。

完成后先交付三种方法对比表、最终权重、过拟合判断、strict parent_group 是否保持改善，以及正式软件建议。除非用户另行批准，不修改正式软件、不合并分支。
