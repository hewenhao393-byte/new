# 水泵六分类故障诊断软件架构说明

## 1. 系统总体架构

软件采用分层模块化结构，界面不直接调用信号处理、特征提取或模型代码。

```text
Streamlit UI 层
        ↓
Service 层
        ↓
Inference 层
        ↓
信号读取、质量检查、预处理与分窗
        ↓
21 维特征提取
        ↓
BP 六分类模型
        ↓
多窗口概率融合
        ↓
Reporting、可视化与 Word 报告
```

## 2. 模块职责

### UI层

`pump_fault_app/ui/` 负责用户输入、页面布局和已有结果展示。它只调用 `pump_fault_app.services`，不会重新读取原始文件或执行 FFT、包络、小波包及模型推理。

### Service层

`pump_fault_app/services/` 负责组织单文件和批量诊断请求，统一返回应用结果对象，并提供报告导出服务。

### Inference层

`pump_fault_app/inference/` 负责正式推理编排：信号读取、质量检查、预处理、分窗、特征提取、模型概率预测和多窗口融合。该层不依赖 Streamlit。

### Reporting层

`pump_fault_app/reporting/` 将正式推理结果组织为报告视图数据，并生成 Word 报告。图形数据只复用 `visualization` 契约，不重新执行诊断算法。

### Presentation层

`pump_fault_app/presentation/` 仅做页面所需的表格行、图表行和状态文本适配，不计算新的诊断指标，也不修改 service 返回结果。

### Tests

`tests/` 覆盖信号处理、特征提取、推理、报告、界面、自检和端到端链路，防止工程优化改变正式诊断结果。

## 3. 正式契约与版本

部署软件的正式 V2 契约入口为 `pump_fault_app/domain/formal_contract.py`。它冻结以下条件：

- 目标采样率：12000 Hz
- 分析频带：10~5000 Hz
- 窗口和步长：2400/1200 点
- 小波包：db6，3 层
- 包络频带：2000~5000 Hz
- 输入特征：固定 21 维
- 输出标签：正常、转子不平衡、联轴器不对中、松动、轴承故障、汽蚀

`pump_fault_app/version.py` 是软件版本、模型版本、特征版本和推理契约版本的唯一来源。`pump_diagnosis/inference_contract.py` 保留为实验脚本的兼容入口，不得作为新增软件模块的依赖。

## 4. 数据流

```text
CSV/TXT 振动信号
        ↓
信号质量检查
        ↓
去直流、重采样与 10~5000 Hz 预处理
        ↓
2400/1200 点窗口分割
        ↓
21 维特征
        ↓
BP 模型窗口级概率
        ↓
采集段级概率融合
        ↓
六分类诊断结果、visualization 和报告数据
```

## 5. 软件特点与边界

- 推理参数、特征顺序和标签顺序均由唯一正式契约约束。
- 模型、界面和报告相互解耦，Streamlit、CLI 和 Word 导出复用同一正式结果。
- 运行告警不会被删除；界面以中性处理状态展示，详细告警仍保留在可展开区域和报告数据中。
- 当前模型主要适用于与训练数据采集条件相近的水泵振动信号。未知泵型、不同测点、传感器或显著不同工况下的结果仅作为辅助参考。
